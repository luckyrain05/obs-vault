# Memory Addresses

- Conceptually, [[ram|RAM]] is an array of ==bytes==, or 8 bits, the smallest addressable unit. Multi-bit values smaller than a byte cannot be read or written individually.
- Each byte has a unique integer index, called a ==memory address==. The first byte sits at index 0, the next at 1, and so on.

```
+---------+------+
| address | byte |
+---------+------+
|    0    | 0x4F |
+---------+------+
|    1    | 0xA2 |
+---------+------+
|    2    | 0x00 |
+---------+------+
|    3    | 0xFF |
+---------+------+
|   ...   | ...  |
+---------+------+
```

**Address Width**

- The address width is the number of bits in an address used in the [[os]]. Commonly denoted as 32-bit system or 64-bit system.
	- 32-bit addresses: $2^{32}$ distinct addresses, or 4 GB.
	- 64-bit addresses: $2^{64}$ distinct addresses, or 16 EB. Current x86-64 hardware uses only 48 of those 64 bits, capping the usable space at 256 TB.

# Pointers

- A ==pointer== is a variable whose value is a memory address. ==Dereferencing== a pointer reads or writes the byte at that address.
- Pointer width equals address width — 4 bytes on a 32-bit system, 8 bytes on a 64-bit system. The pointer itself sits at some address, and the address it stores points at another.

**Pointer arithmetic**

- Adding `n` to a `T *` advances the address by `n * sizeof(T)` bytes, not by `n` bytes. The language scales by element size so that `p[n]` lands on the n-th element of an array of `T`, not the n-th byte.
- Subtracting two pointers of the same type yields the count of elements between them, again scaled by `sizeof(T)`.

# Endianness

- A single byte fits at a single address. But most useful values like integers are larger than a byte. A 32-bit integer occupies 4 consecutive byte addresses.
- The order in which those bytes are stored is the endianness.

**Little-endian**

- Least significant byte at the lowest address. x86 and ARM (default).

**Big-endian**

- Most significant byte at the lowest address. Used by network protocols ("network byte order").

```
the 32-bit integer 0x12345678

little-endian (x86):                 big-endian:
+------+------+------+------+        +------+------+------+------+
| 0x78 | 0x56 | 0x34 | 0x12 |        | 0x12 | 0x34 | 0x56 | 0x78 |
+------+------+------+------+        +------+------+------+------+
addr+0  +1     +2     +3             addr+0  +1     +2     +3
```

- Pointer arithmetic is unaffected — a pointer to the integer points at `addr+0` either way. Only direct byte-level access exposes the difference.

# Address Space

- Programs are given a contiguous range of addresses called its address space. 
- From the process's view, memory is just a flat array of bytes from address 0 up to the maximum allowed by the architecture.
- The address space is typically consisted of the following two main segments. 
	1. ==Compile-time Allocations==.
	2. ==Run-time Allocations==.
- May slightly differ depending on the programming language.

```
     high addresses
+-----------------------+
|                       |
|.......................|
|         Stack         |
|           |           |
|           v           |
|                       |
|                       |

|           |           |
|         Heaps         |
|.......................|
|                       |
+-----------------------+
|        globals        |
+-----------------------+
| compiled instructions |
+-----------------------+
      low addresses
```

# [[compilers#Compile Time vs Runtime|Compile-Time]] Allocations

- This region of the address space is allocated before the program starts running.
- Permanent, lives throughout the [[processes]]' lifetime.
- Fixed size at the lowest memory address, but data is mutable.
- Consisting of two main segments:
	1. Compiled Instructions
	2. Process Globals

# Compiled instructions

- The machine instructions the [[cpu]] executes generated by the [[compilers|compiler]].
- Readable but immutable, the process may not modify it's own instructions.

# Globals

- Variables shared by the entire file, declared outside of any wrappers.
- Read and writable, the variables were declared to be used.

# [[compilers#Compile Time vs Runtime|Run-Time]] Allocations

- The [[cpu]] manages this region in real-time while reading the compiled instructions.
- Consisting of two main segments as well:
	- Stack
	- Heap
